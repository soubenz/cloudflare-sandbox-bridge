How it works

Three steps, every lab

The format doesn't change. What's broken does.

01

Get a real environment

A hosted container spins up for you: a Python agent, the services it talks to, sometimes a real model behind Cloudflare AI Gateway. Nothing simulated, nothing to install.

02

Break it, or fix it

Every lab is a build or a break-fix. You either build the missing component or find and fix what's actually failing — reading real code and real logs, not answering a quiz about them.

03

Outcome-based grading

A grader replays the scenario and checks what the services themselves recorded — deliveries, spend, retries, traces. It never reads your source or takes a model's word for it.

Why it's graded this way

What makes it different

→

Grading reads outcomes, not code

Every check is a fact recorded by the system itself — a mailbox log, a gateway ledger, a trace — never a read of your source or a model's opinion of your wording. A correct fix passes no matter how you got there, and a cosmetic one doesn't.

→

Every lab is checked against a real wrong answer

Before a lab ships, it's verified against an actual broken solution, not just the happy path. If the wrong fix would pass, the lab isn't done.

→

The bugs are the kind that actually ship

Retried side effects, budgets nobody keyed by tenant, a status line trusted instead of the body — the failures here are lifted from real incidents, not written to teach a concept in isolation.
